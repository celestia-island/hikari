# ドックの配置：pin と ride

ドックはある領域に属するクロームだ——ボード下のバー、隅のページャー。スクロール領域では
ドックは `HkScrollContainer` のスロット（`dockBottom` / `dockTop`）からマウントされ、
コンテナは下部ドックの配置方法を二つ用意している（`dockMode`）。

## `pin` — 既定

ドックはスクロールビューポートの**スクロールしない** flex 兄弟になる。コンテナの下端に
固定され、決してスクロールせず、ビューポートはその高さだけ縮む。

領域の枠を所有するクロームに向く——ログ上のプログレスバー、パネル自身の端に揃うツールバー。

コンテンツ末端とドックの間の余白はウィンドウの余り次第で、コンテンツが一画面に満たない
ときは、その余り高さが両者の間に死んだ帯として残る。

## `ride`

ドックはビューポートの内容フローに入り、コンテンツの後ろ、**実測したドック高さちょうど**の
スペーサーの後ろに置かれ、`position: sticky; bottom: 0` で可視の下端に貼り付く：

- コンテンツが短い——ドックはコンテンツ末端に追従して自分のフロー位置に留まり、その上の
  余白はちょうどドック一つ分、ウィンドウの余り高さはドックの**下**に落ちる；
- コンテンツが長い——ドックは可視の下端に留まり（決して流れ去らない）、スクロール末端でも
  同じくドック一つ分の余白が開く。

コンテンツに属するクロームに向く——巡航キャンバスで最後の行の下に立つ下部バー。コンテナが
ドックを実測して `--hk-scroll-dock-bottom` を公開するので、ホストがスペーサーのレシピや
マジックナンバーを手書きする必要はなく、余白はドックの再レイアウト（行の変化、ブレーク
ポイントの切り替え）に追従する。

## ride はフレーム単位の予約ではない

ride は、内容フローの外からスクロール領域に浮かぶドックのためにビューポート上で `::after`
により `ドック高さ + 呼吸` を予約していた、あの廃止済みのレシピでは**ない**。あの帯は
スクロール末端より前に死んだ余白として現れ、ドックがコンテンツに追従することもなかった。
ride のドック本体はフロー内の子ノードであり、どこか別で描かれるもののために空間を前もって
確保しない。sticky こそが、余白をウィンドウではなくコンテンツに追従させる仕組みだ。

## 選び方

| ホスト | 配置 |
|---|---|
| スクロール領域で、クロームがコンテンツに属する | `dockMode="ride"` |
| スクロール領域で、クロームが領域の枠を所有する | `dockMode="pin"` |
| キャンバス / ページのオーバーレイで、スクロール領域が所有しない | `HkDockBar` |

`ride` は垂直方向の末尾にのみ存在する。`axis="horizontal"` のコンテナは `pin` のまま
だ——そちらの末尾は交差軸だからである。
