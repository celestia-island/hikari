# 通知センター：閉じる文法

通知を閉じることは、決して失うことではない。消える面を持つすべての対象——
隅のトースト スタック、フローを塞ぐ確認ゲート、全画面緊急警告バンド、
ホストの常駐チップ——は、表示した内容を通知センターのジャーナルに記録し、
ベルがホストのマウントした任意の場所からそのリストを再呼び出しできる。

## デフォルトで収集するもの

ユーザー裁定（2026-11-15）により、既定で収集するのは見返す価値のあるトーン：

- error / warning トースト。回答済みのブロッキング ゲート。緊急警告の全
  エピソード（active・snoozed・cleared——解決済みの条件も見返し可能のまま）。
  ホストが明示記録した常駐チップ。
- success / info / loading トーストは push 単位の opt-in
  （`journal: true`）——3 秒の「保存しました」をすべて記録しては、
  リストがノイズに沈むだけ。

## 保持と再生

ジャーナルはセッション単位で保持：sessionStorage はリロードを跨いで生存し、
ブラウザ セッションとともに消える。加えて 100 件のリング バッファ
（最終更新時刻で最古を落とす）。レコードは**記録**にすぎない——トーストの
アクション ボタンは呼び出し側のクロージャであり、リストから再発火することは
ない。唯一の可逆例外は snooze された緊急警告：エントリは実際の unsnooze 経路
を持ち（「再表示」で警告バンドが戻る）。

## 既読ルール

パネルを開くことが既読の受領そのもの。ベル自身のドット（アイコン ボタン内蔵の
マークで、ラッパーのバッジではない）が答えるのは「何か見逃していないか」であり、
「今画面に何かがあるか」ではない。

## 配置

配置は下流（ホスト）が決める——hikari が所有するのは保存文法とコンポーネント。
管理/コンソール面のリファレンス配置：右上アクション クラスタ、**設定ギアの左**の
ベル アイコン ボタン（chest webui の HeaderEndCluster）。追加のウィンドウ
操作ボタンを持つデスクトップ シェルは影響を受けない（ギアの右側にあるため）。
ページ本文のボタンではなく、ページ スコープのアクション スロット経由でも
登録しない（ページ クロームはページとともにアンマウントされる。ベルはグローバル）。

トリガーはサイズ ラダー上の `HkIconButton`、面は `sheetOnMobile` の
`HkPopover`——広い画面ではアンカー ポップオーバー、電話ではボトム シート、
ブレークポイントを跨ぐライブ切替も安全。

## リファレンス実装

`runtime/notificationCenter.ts`（ジャーナルと各ソースの記録フック）+
`components/HkNotificationBell.tsx`（ベル + パネルの一体構成）。
ソースは `recordNotification` / `setNotificationState` で書き込み、
ホストは `<HkNotificationBell />` をマウントして住まいを決める。
