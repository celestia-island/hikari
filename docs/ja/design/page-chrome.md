# ページクローム：アクションバーの文法

管理画面とコンソール画面は、1 つのヘッダー契約を共有します。ページは「用途を宣言する
スロット」を通じて右上のアクションクラスタを所有し、ページの主要な入口はページ本文では
なくクラスタ内に住みます。

## 正規スロット

登録は必ず用途を宣言します。クラスタは正規スロットを固定順位で描画し、ビューが登録した
順序には従いません：

```text
[新規作成][フィルタ][検索][更新][ウィンドウ]
```

正規スロットに該当しない用途の登録はカスタム扱いです。正規ゾーンの後ろに、登録の逆順で
右から左へ詰められます。正規ゾーンが動くことはありません。

## 新規作成ルール

ページの主たる作成アクション——新しいトップレベル実体（プロバイダー、チャネル、グループ、
アクセスルール、共有テーマライン上のテーマ）を作る入口——は、**右上クラスタ内のプラス
アイコンボタン、更新の左**です。ページ本文内の独立ボタンであってはいけません。

本文ボタンが表示していたはずのラベルは、そのボタンのアクセシブル名とツールチップに
なります。作成用ダイアログの所有権はページ側に残ります。

**文脈内の追加は免除されます。** エディタ・ダイアログ・ウィザード・カード内のサブリストに
行を追加するプラス（「モデル行を追加」「メンバーを追加」「マウント方式を追加」）は、その
局所文法の一部であり、ページの作成アクションではありません。その場に留まります。

## ジオメトリ

クラスタは 1 列の chrome です。すべてのアイコンボタンは同じサイズラダー
（`useChromeActionSize`）を歩み、グリフは 16px です。固定サイズのボタンがラダーサイズの
隣に混ざると、別ファミリーのボタンに見えます。クラスタは共有ヘルパーで組み立て、手打ちの
サイズは禁じます。

## リファレンス実装

chrome は hikari が提供します：`HkAdminHeader` のアクション行、`HkIconButton`、
`useChromeActionSize`。ホストは上記スロットを描画するアクションバーコンテキスト経由で
登録します。chest webui の `useActionBar` / `usePageCreateAction` がこの文法の
リファレンス実装です。

## モバイル折りたたみ

ヘッダー中央スロットやフッター中央スロットに固定されたボタン群は、電話幅の
ビューポート（<768、`useBreakpoint().isMobile`——sheet ファミリーの閾値）で
折りたたまれる：ストリップは**現在の項目**を読み上げるセレクト式トリガーになり、
選択肢はボトムシートとして開く（`HkSelectPanel` の `sheetOnMobile`）。
両形態は同一の value 契約を共有し、`?tab=` ディープリンクはブレークポイントを
跨いでも生き残る。`HkAdaptiveTabs` が既定の実装。専用行を持つ動的
プロジェクト切替器（プラットフォームスイッチャー）は免除される特例であり、
模範ではない。
