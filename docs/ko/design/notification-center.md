# 알림 센터: 닫힘 문법

알림을 닫는 것이 곧 잃어버리는 것이어서는 안 된다. 사라지는 표면 전부 —
모서리 토스트 스택, 흐름을 막는 확인 게이트, 전체 화면 긴급 경고 밴드,
호스트의 상주 칩 — 는 표시한 내용을 알림 센터 저널에 기록하고, 벨이
호스트가 마운트한 어디에서든 그 목록을 다시 불러낸다.

## 기본 수집 대상

사용자 재정(2026-11-15)에 따라, 기본으로는 다시 볼 가치가 있는 톤만:

- error / warning 토스트. 답변된 블로킹 게이트. 긴급 경고의 모든 에피소드
  (active · snoozed · cleared — 해소된 조건도 검토 가능한 상태로 유지).
  호스트가 명시 기록한 상주 칩.
- success / info / loading 토스트는 push 단위 opt-in(`journal: true`) —
  3초짜리 "저장했습니다"까지 기록하면 목록이 소음에 잠긴다.

## 보존과 재생

저널은 세션 단위 보존: sessionStorage는 리로드를 넘어 생존하고 브라우저
세션과 함께 사라진다. 여기에 100개 링 버퍼(마지막 갱신 시각 기준 최oldest
탈락). 레코드는 **기록**일 뿐 — 토스트의 액션 버튼은 호출자 클로저이며
목록에서 재발화되지 않는다. 유일한 가역 예외는 snooze된 긴급 경고:
엔트리가 실제 unsnooze 경로를 지니며("다시 표시"가 밴드를 되돌린다).

## 읽음 규칙

패널을 여는 것이 곧 읽음 영수증이다. 벨 자신의 도트(아이콘 버튼 내장 마크이지
감싸는 배지가 아님)가 대답하는 것은 "무엇을 놓쳤는가"이지
"지금 화면에 무엇이 있는가"가 아니다.

## 배치

배치는 하류(호스트)가 결정한다 — hikari는 저장 문법과 컴포넌트만을 소유한다.
관리/콘솔면의 참조 배치: 오른쪽 위 액션 클러스터, **설정 기어의 왼쪽** 벨
아이콘 버튼(chest webui의 HeaderEndCluster). 추가 창 제어 버튼을 지닌
데스크톱 셸은 영향받지 않는다(기어 오른쪽에 있으므로). 페이지 본문 버튼이
아니며, 페이지 스코프 액션 슬롯으로 등록하지도 않는다(페이지 크롬은 페이지와
함께 언마운트된다. 벨은 전역 요소).

트리거는 크기 사다리의 `HkIconButton`, 표면은 `sheetOnMobile`의
`HkPopover` — 넓은 화면에서는 앵커 팝오버, 전화에서는 바텀 시트,
브레이크포인트를 넘는 실시간 전환도 안전.

## 참조 구현

`runtime/notificationCenter.ts`(저널과 각 소스의 기록 훅) +
`components/HkNotificationBell.tsx`(벨 + 패널 일체 구성).
소스는 `recordNotification` / `setNotificationState`로 기록하고,
호스트는 `<HkNotificationBell />`을 마운트해 자리를 정한다.
