# Центр уведомлений: грамматика исчезновения

Закрыть уведомление — не значит потерять его. Каждая исчезающая
поверхность — угловая стопка тостов, блокирующие подтверждения,
полноэкранная аварийная полоса, постоянные чипы хоста — записывает
показанное в журнал центра уведомлений, и колокольчик вновь вызывает
список в любом месте, куда хост его смонтировал.

## Что попадает в журнал по умолчанию

По решению пользователя (2026-11-15) — только тоны, достойные второго
взгляда:

- тосты error и warning; обработанные блокирующие подтверждения; все
  эпизоды аварийного оповещения (active, snoozed и cleared —
  устранённые условия остаются обозримыми); постоянные чипы, записанные
  хостом явно.
- тосты success / info / loading входят по push с `journal: true` —
  журналировать каждое трёхсекундное «Сохранено» значит утопить список
  в шуме.

## Хранение и повтор

Журнал живёт в рамках сессии: sessionStorage переживает перезагрузки и
исчезает вместе с сессией браузера, поверх кольцевого буфера на 100
записей (старейшая выбывает по времени последнего обновления). Запись —
это только ЗАПИСЬ: кнопка действия тоста есть замыкание вызывающего и
никогда не переигрывается из списка. Единственный обратимый случай —
аварийное оповещение в snooze: его запись несёт настоящий путь unsnooze
(«Показать снова» возвращает полосу).

## Правило прочтения

Открытие панели и есть квитанция о прочтении. Точка самой колокольчика
(встроенная метка кнопки-иконки, а не обёрточный бейдж) отвечает на
«пропустил ли я что-то», а не «есть ли что-то на экране прямо сейчас».

## Размещение

Размещение принадлежит потребителю — hikari владеет лишь грамматикой
хранения и компонентами. Референсное размещение для админ/консольных
лиц: кнопка-колокольчик в кластере действий правого верхнего угла,
**слева от шестерёнки настроек** (HeaderEndCluster веб-интерфейса
chest) — оболочки рабочего стола с лишними кнопками окна остаются
нетронутыми в правом краю. Это никогда не кнопка в теле страницы и
не регистрация через слот действий с областью видимости страницы
(хром страницы демонтируется вместе со страницей; колокольчик —
глобальная вещь).

Триггер — `HkIconButton` на лестнице размеров хрома; поверхность —
`HkPopover` с `sheetOnMobile`: якорный флайаут на широких экранах,
нижний лист на телефонах, с живо-безопасным переходом точки перелома.

## Референсная реализация

`runtime/notificationCenter.ts` (журнал и хуки источников) +
`components/HkNotificationBell.tsx` (колокольчик + панель одной
композицией). Источники пишут через `recordNotification` /
`setNotificationState`; хосты монтируют `<HkNotificationBell />` и
решают, где он живёт.

Записываемые хостом id делят одну плоскую строковую пространство с встроенными зеркалами: префиксы `toast:` / `blocking:` / `emergency:` зарезервированы ими — хост, записывающий постоянные чипы или собственные записи, выбирает свой префикс (напр. `myapp:`), чтобы пользовательский id никогда не мог перехватить встроенный эпизод.
