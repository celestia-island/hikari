# 停靠位：pin 与 ride

dock 是归属于某个区域的骨架元素——看板底部的一条栏、角落里的一组翻页器。在滚动区域里，
dock 通过 `HkScrollContainer` 的插槽（`dockBottom` / `dockTop`）挂载，容器为底部 dock
提供了两种落位（`dockMode`）。

## `pin` —— 默认

dock 是滚动视口的**非滚动** flex 兄弟节点：它固定贴在容器底边，永不被滚动，视口按它的
高度收缩。

适用于「占据区域边框」的骨架——日志上方的进度条、与面板自身边缘对齐的工具条。

内容末端与 dock 之间的空气由窗口的剩余高度决定：内容不满一屏时，两者之间会一直留着一段
窗口剩余高度造成的死气。

## `ride`

dock 进入视口的内容流，排在内容之后，前面垫一个**等于容器实测 dock 占位高**的 spacer，
并以 `position: sticky; bottom: 0` 贴在可见底边：

- 内容短——dock 跟随内容下沿停在自身流位置，它上方的空气就是这份实测占位高，窗口多出来的
  高度落到 dock **下面**；
- 内容长——dock 停在可见底边上（永不滚走），滚动到底时同样留出这份空气。

「dock 占位高」是容器实测并发布为 `--hk-scroll-dock-bottom` 的那个盒子高度——dock 自己的
占位盒，**不一定是可见 dock 面**：宿主放在这条带内的空间（dock inset、某一行自带的末行内边距）
会额外叠加，所以空气相对可见 dock 的偏差就是宿主自己的内边距。宿主读这个发布值即可，不必手写
spacer 配方或魔数，空气也会跟随每一次 dock 重排（某一行变化、断点切换）。

ride 宿主还必须让内容能够结束在**视口底边之上**：把内容盒撑到视口高的规则
（`min-height: 100%`）会让 in-flow 的 spacer 与 dock 落在折线之外，dock 只能贴边，空气又退回
窗口剩余高。`HkKanban` 会在 ride 板上放开自己的 lanes 盒；自建宿主照做。

出于同一原因，`autoFollow` 与 ride dock 不支持同开：它会把内容盒按整屏高度底对齐，ride 尾部因此落到视口折线之外。开发构建里两者同时开启时容器会警告一次。

## ride 不是 frame 级预留

ride **不是**那条已退役的配方：在视口上用 `::after` 为「漂浮在滚动区之上、位于内容流之外」
的 dock 预留 `dock 高度 + 呼吸`；也**不是**「预留第二个 dock 的空白」。那条配方会在滚到底之前
就出现死气，且 dock 从不跟随内容。ride 的 dock 本体就是内容流里的子节点：没有任何空间是为
别处绘制的东西预留下来的，而 sticky 才是让空气跟随内容而不是窗口的原因。

## 如何选择

| 宿主 | 落位 |
|---|---|
| 滚动区域，骨架属于内容 | `dockMode="ride"` |
| 滚动区域，骨架占据区域边框 | `dockMode="pin"` |
| 画布 / 页面浮层，没有滚动区域拥有它 | `HkDockBar` |

`ride` 只存在于垂直尾部：`axis="horizontal"` 的容器保持 `pin`，因为它们的尾部是交叉轴。
