# 停靠位：pin 与 ride

dock 是归属于某个区域的骨架元素——看板底部的一条栏、角落里的一组翻页器。在滚动区域里，
dock 通过 `HkScrollContainer` 的插槽（`dockBottom` / `dockTop`）挂载，容器为底部 dock
提供了两种落位（`dockMode`）。

## `pin` —— 默认

dock 是滚动视口的**非滚动** flex 兄弟节点：它固定贴在容器底边，永不被滚动，视口按它的
高度收缩。

适用于「占据区域边框」的骨架——日志上方的进度条、与面板自身边缘对齐的工具条。

内容末端与 dock 之间的空气由窗口的剩余高度决定：内容不满一屏时，两者之间会一直留着一段
窗口剩余高度造成的死气。

## `ride`

dock 进入视口的内容流，排在内容之后，前面垫一个**恰好等于实测 dock 高度**的 spacer，
并以 `position: sticky; bottom: 0` 贴在可见底边：

- 内容短——dock 跟随内容下沿停在自身流位置，它上方的空气恰好一个 dock 高度，窗口多出来
  的高度落到 dock **下面**；
- 内容长——dock 停在可见底边上（永不滚走），滚动到底时同样留出一个 dock 高度的空气。

适用于「归属于内容」的骨架——巡航画布里站在最后一行下方的底部栏。容器会实测 dock 高度
并发布 `--hk-scroll-dock-bottom`，宿主不必再手写 spacer 配方或魔数，空气也会跟随每一次
dock 重排（某一行变化、断点切换）。

## ride 不是 frame 级预留

ride **不是**那条已退役的配方：在视口上用 `::after` 为「漂浮在滚动区之上、位于内容流之外」
的 dock 预留 `dock 高度 + 呼吸`。那条配方会在滚到底之前就出现死气，且 dock 从不跟随内容。
ride 的 dock 本体就是内容流里的子节点：没有任何空间是为别处绘制的东西预留下来的，而
sticky 才是让空气跟随内容而不是窗口的原因。

## 如何选择

| 宿主 | 落位 |
|---|---|
| 滚动区域，骨架属于内容 | `dockMode="ride"` |
| 滚动区域，骨架占据区域边框 | `dockMode="pin"` |
| 画布 / 页面浮层，没有滚动区域拥有它 | `HkDockBar` |

`ride` 只存在于垂直尾部：`axis="horizontal"` 的容器保持 `pin`，因为它们的尾部是交叉轴。
