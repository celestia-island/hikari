# 页面骨架：动作区语法

管理与控制台页面共用同一份页头契约：页面通过「声明用途的槽位」拥有右上角动作区，
页面的主要入口住在动作区里——而不是页面正文里。

## 规范槽位

每个注册都声明一个用途；动作区按槽位的固定次序渲染，与视图注册的先后无关：

```text
[新增][筛选][搜索][刷新][窗口]
```

用途不属于规范槽位的注册是自定义项：排在规范区之后、按注册的逆序由右向左填充，
规范区永远不被挤动。

## 新增规则

页面的主创建动作——创建一个新的顶层实体（一个提供商、一个渠道、一个分组、一条
准入规则、共享主题线上的一套主题）——是**右上角动作区里的加号图标按钮，位于刷新
左边**。它绝不是页面正文里的独立按钮。

原本印在正文按钮上的可见文案，成为该按钮的无障碍名称与悬浮提示；创建用的对话框
仍由页面自己拥有。

**局部添加不受此限。** 在编辑器、对话框、向导或卡片内部的子列表里加一行（「添加
模型行」「添加成员」「添加挂载方案」）属于那层局部语法，不是页面的创建动作，留在
原地。

## 几何

动作区是一整排 chrome：每个图标按钮都走同一套尺寸阶梯（`useChromeActionSize`），
图标配 16px。一个写死尺寸的按钮混在阶梯尺寸的邻居中间，会被读成另一族按钮——
用共享的组合式函数组装动作区，不要手钉尺寸。

## 参考实现

chrome 由 hikari 提供：`HkAdminHeader` 的动作行、`HkIconButton` 与
`useChromeActionSize`。宿主经渲染上述槽位的动作区上下文注册；chest webui 的
`useActionBar` / `usePageCreateAction` 是这套语法的参考实现。

## 移动端折叠

锚定在页眉中槽或页脚中槽的按钮组，在手机宽度视口（<768，`useBreakpoint().isMobile`——
sheet 家族的阈值）折叠为：原按钮组变成一个读出**当前项**的下拉式触发钮，选项
以底部 sheet 展开（`HkSelectPanel` 的 `sheetOnMobile`）。两套形态共用同一份
value 契约，`?tab=` 深链跨断点不受影响。`HkAdaptiveTabs` 是默认实现；
自带专属行的动态项目列表切换器（平台切换器）是豁免的特例，不是可照抄的模式。
