# 页面骨架：动作区语法

管理与控制台页面共用同一份页头契约：页面通过「声明用途的槽位」拥有右上角动作区，
页面的主要入口住在动作区里——而不是页面正文里。

## 规范槽位

每个注册都声明一个用途；动作区按槽位的固定次序渲染，与视图注册的先后无关：

```text
[新增][筛选][搜索][刷新][窗口]
```

用途不属于规范槽位的注册是自定义项：排在规范区之后、按注册的逆序由右向左填充，
规范区永远不被挤动。

## 新增规则

页面的主创建动作——创建一个新的顶层实体（一个提供商、一个渠道、一个分组、一条
准入规则、共享主题线上的一套主题）——是**右上角动作区里的加号图标按钮，位于刷新
左边**。它绝不是页面正文里的独立按钮。

原本印在正文按钮上的可见文案，成为该按钮的无障碍名称与悬浮提示；创建用的对话框
仍由页面自己拥有。

**局部添加不受此限。** 在编辑器、对话框、向导或卡片内部的子列表里加一行（「添加
模型行」「添加成员」「添加挂载方案」）属于那层局部语法，不是页面的创建动作，留在
原地。

## 几何

动作区是一整排 chrome：每个图标按钮都走同一套尺寸阶梯（`useChromeActionSize`），
图标配 16px。一个写死尺寸的按钮混在阶梯尺寸的邻居中间，会被读成另一族按钮——
用共享的组合式函数组装动作区，不要手钉尺寸。

## 参考实现

chrome 由 hikari 提供：`HkAdminHeader` 的动作行、`HkIconButton` 与
`useChromeActionSize`。宿主经渲染上述槽位的 `provideActionBar` /
`useActionBar` composable 对注册；它是这套语法的参考实现。

## 移动端折叠

锚定在页眉中槽或页脚中槽的按钮组，在手机宽度视口（<768，`useBreakpoint().isMobile`——
sheet 家族的阈值）折叠为：原按钮组变成一个读出**当前项**的下拉式触发钮，选项
以底部 sheet 展开（`HkSelectPanel` 的 `sheetOnMobile`）。两套形态共用同一份
value 契约，`?tab=` 深链跨断点不受影响。`HkAdaptiveTabs` 是默认实现；
自带专属行的动态项目列表切换器（平台切换器）是豁免的特例，不是可照抄的模式。

## 选择器 sheet 与钉住的搜索框

下拉面（`HkSelectPanel`——`HkSelect` / `HkMenu` / 各类芯片选择器底下那一层）
有两条内容带，什么东西归哪条带没有商量余地：

- **`default` 滚动。** 行、卡片、目录——一切可能超出面板高度的内容。
- **`pinnedHeader` 不滚动。** 列表滚动时也必须够得着的 chrome：首当其冲是
  实时过滤的搜索框。它在两种形态下都渲染在滚动区之外——手机上是标题行
  下方的一条带，桌面上是 popout 列的头部（此时由 body 承担唯一的滚动条）。
  搜索框放在滚动内容里、一滑就跟着滚走，是缺陷而不是风格选择（2026-11-27）。

选择器/菜单家族的手机 sheet 贴合内容高度，最多到**视口的 80%**；更长的内容在
内部滚动。为桌面 popout 调的盖帽（`maxHeight`，例如 `min(18rem, 45dvh)`）永远
不会作用到 sheet 上。sheet 还会截断滚动链：在手柄、标题行或钉住带上滑动，
不会拖动后面的页面。

## 列表动效

只要列表项发生变动——新增、移除、重排——位移一律走 hikari 的
`HkListTransition`（带 key 的 `TransitionGroup`，FLIP 向运行时动画总线报备），
不许手搓补间。所有列表形表面（行、卡片、瀑布流）共用一个默认：移动轨道 0.3s，
进入与离开各 0.15s，并且与移动同时开始。宿主用 `duration` / `enterDuration` /
`leaveDuration` 三个 prop 定制（CSS 时间；只给 `duration` 时两半自动推导）。
`surface` 是唯一例外（本身是窗口的行保留窗口家族的进出场节奏）。

宿主的两条常设规则：直接住在滚动视口里的列表保持 `move` 关闭（离场幽灵钉在最近的定位祖先上，滚动视口并不是视觉上的列表框）；列表行永不写 `transition: all`——原语的轨道会在一次编排的时长内接管该行的 `transition`，`all` 轨道的悬停脸色会在那个窗口里丢掉。

多选选择器（`HkAffixPicker` 的 `multi` 模式、`layout="rows"`）不会为选中项在
搜索框前面新建任何东西：勾选的行带左侧勾选标记，按目录顺序浮到列表前部、
以一条分隔线与其余行隔开；点一下即切换，行会滑到或滑回自己的位置。
`layout="tags"` 是值编辑器形态（每条显示各自填写的值），保留搜索框上方的标签条。

## 页脚角落文本

页眉/页脚的六个角落（左/中/右 ×2）显示文本，一律用 hikari 的 `HkCornerText`：
一个实例 = 一个角落的一条文本道。

- `align` 决定对齐：`start`（左角）/`center`（中道）/`end`（右角）；条目换行后
  继续贴着同一侧——右角的文本折行仍靠右。
- 条目是 `nowrap` 原子：条目**之间**换行，条目内部永不折行（备案号不得断在序号
  中间）。
- 默认 chrome 弱墨（`text-2xs` + 0.6 不透明度）；`muted: false` 恢复全墨。
- 一个角落要多行（身份行 + 备案行）就纵向堆叠多个实例——固定 3rem 状态带内
  容得下两行 text-2xs。
- `items` 的条目形状是 `{ key, text, href? }`：`key` 是列表渲染的稳定标识，
  `text` 是显示文本（备案号、系统名……），`href` 可省略——省略渲染成普通的
  `<span>`，给出则渲染成链接。
- 带 `href` 的条目一律新标签页打开：`target="_blank"` + `rel="noopener noreferrer"`
  （与备案号同一契约——外站不得持有登录页窗口的句柄）。这是组件的行为，宿主
  不要自己再包一层 `<a>`。
- 链条目用 `items` + `as="nav"` + `ariaLabel`；自由内容（状态芯片）走默认
  插槽，排在 `items` 之后。

宿主不得再手写 `flex-wrap: nowrap` 的单行挤压道，也不得让文本溢出固定高度带。
参考实现：`HkCornerText`。
