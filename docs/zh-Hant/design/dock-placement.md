# 停靠位置：pin 與 ride

dock 是歸屬於某個區域的骨架元素——看板底部的一條列、角落裡的一組翻頁器。在捲動區域裡，
dock 透過 `HkScrollContainer` 的插槽（`dockBottom` / `dockTop`）掛載，容器為底部 dock
提供兩種落位（`dockMode`）。

## `pin` —— 預設

dock 是捲動視口的**非捲動** flex 兄弟節點：它固定貼在容器底邊，永不被捲動，視口依它的
高度收縮。

適用於「佔據區域邊框」的骨架——日誌上方的進度條、與面板自身邊緣對齊的工具列。

內容末端與 dock 之間的空氣由視窗的剩餘高度決定：內容不滿一屏時，兩者之間會一直留著一段
視窗剩餘高度造成的死氣。

## `ride`

dock 進入視口的內容流，排在內容之後，前面墊一個**等於容器實測 dock 佔位高**的 spacer，
並以 `position: sticky; bottom: 0` 貼在可見底邊：

- 內容短——dock 跟隨內容下沿停在自身流位置，它上方的空氣就是這份實測佔位高，視窗多出來的
  高度落到 dock **下方**；
- 內容長——dock 停在可見底邊上（永不捲走），捲動到底時同樣留出這份空氣。

「dock 佔位高」是容器實測並發佈為 `--hk-scroll-dock-bottom` 的那個盒子高度——dock 自己的
佔位盒，**不一定是可見 dock 面**：宿主放在這條帶內的空間（dock inset、某一行自帶的末行內距）
會額外疊加，所以空氣相對可見 dock 的偏差就是宿主自己的內距。宿主讀這個發佈值即可，不必手寫
spacer 配方或魔數，空氣也會跟隨每一次 dock 重排（某一行變化、斷點切換）。

ride 宿主還必須讓內容能夠結束在**視口底邊之上**：把內容盒撐到視口高的規則
（`min-height: 100%`）會讓 in-flow 的 spacer 與 dock 落在折線之外，dock 只能貼邊，空氣又退回
視窗剩餘高。`HkKanban` 會在 ride 板上放開自己的 lanes 盒；自建宿主照做。

## ride 不是 frame 級預留

ride **不是**那條已退役的配方：在視口上用 `::after` 為「漂浮在捲動區之上、位於內容流之外」
的 dock 預留 `dock 高度 + 呼吸`；也**不是**「預留第二個 dock 的空白」。那條配方會在捲到底之前
就出現死氣，且 dock 從不跟隨內容。ride 的 dock 本體就是內容流裡的子節點：沒有任何空間是為
別處繪製的東西預留下來的，而 sticky 才是讓空氣跟隨內容而不是視窗的原因。

## 如何選擇

| 宿主 | 落位 |
|---|---|
| 捲動區域，骨架屬於內容 | `dockMode="ride"` |
| 捲動區域，骨架佔據區域邊框 | `dockMode="pin"` |
| 畫布 / 頁面浮層，沒有捲動區域擁有它 | `HkDockBar` |

`ride` 只存在於垂直尾部：`axis="horizontal"` 的容器保持 `pin`，因為它們的尾部是交叉軸。
