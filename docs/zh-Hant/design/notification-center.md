# 通知中心：關閉語法

關閉一條通知絕不等於丟失它。每一個會消失的面——角落 toast 堆疊、阻斷式確認門、
全螢幕緊急警告帶、宿主的駐留 chip——都要把它展示過的內容記入通知中心帳本，
然後由一枚鈴鐺在宿主掛載的任意位置把這份列表重新呼出。

## 預設收納什麼

按用戶裁決（2026-11-15），預設只收值得回看的：

- error / warning toast；已答覆的阻斷門；全部緊急警告 episode
  （active、snoozed、cleared——已恢復的條件保留可回看）；宿主顯式記帳的駐留 chip。
- success / info / loading toast 逐條 opt-in（push 時 `journal: true`）——
  把每條 3 秒的「已儲存」都記進列表只會把有用資訊淹沒在噪音裡。

## 留存與重放

帳本是會話級留存：sessionStorage 跨重新整理存活、隨瀏覽器工作階段消失，
外加 100 條環形緩衝（按最後更新時間丟最舊）。記錄只是**記錄**——
toast 的動作按鈕是呼叫方閉包，永遠不會從列表裡重放。唯一可逆的例外是
被 snooze 的緊急警告：條目自帶真實的解除隱藏通路（「重新顯示」讓警告帶回歸）。

## 已讀規則

打開面板本身就是已讀回執。鈴鐺自己的下標點（圖示按鈕內建 dot，不是外包一層角標）
回答的是「我是不是錯過了什麼」，不是「現在螢幕上有沒有東西」。

## 擺放

擺放歸宿主決定——hikari 只擁有儲存語法與元件。管理/控制台面的參考擺放：
右上角動作區、**設定齒輪左側**的鈴鐺圖示按鈕（chest webui 的
HeaderEndCluster），帶額外視窗控制鈕的桌面殼不受影響（它們在齒輪右側）。
它絕不是頁面正文按鈕，也絕不走頁面作用域的動作槽註冊（頁面 chrome 隨頁卸載，
鈴鐺是全域件）。

觸發鈕是尺寸階梯上的 `HkIconButton`；面板是 `sheetOnMobile` 的
`HkPopover`——寬螢幕為錨定彈層，手機為底部 sheet，跨斷點即時切換安全。

## 動效

列的增刪由 `HkListTransition`（程式庫自身的清單原語——模態麵包屑、標籤輸入、
密碼面板、前後綴選擇器與瀑布流都騎它）編排：採 `pop` 變體
（從輕微縮放沉降下來的淡入）並開啟 FLIP 位移，餘下的列滑入被關閉列讓出的空間。
有兩條性質來自原語與平台、不需要鈴鐺自己實作：原語會把每一批 enter/leave
**上報**給執行期動畫上下文（`runtime/animationBus.ts`，讓 JS 側知道有過渡在飛），
而它自帶的 reduced-motion 規則與全域 CSS 動畫開關
（`html[data-css-animations="0"]`）會整體收斂這套動作。

三條可核對的後果：

- 開啟面板**不會**重播清單的入場（`appear` 保持關閉）——只有真正抵達或離開的列才動。
- 清單外層容器跨過空態切換而存活：沒有列的帳本仍把清單掛在面板上，
  因為拆掉 transition group 會在半途取消正在離開的 ghost。
- 空態交接分兩步：最後一列（或「清空全部」）淡出的這段時間裡，清單保持原有高度
  ——離開的列是被定位在捲動容器**內部**的，清單一收縮就會把它自己的 ghost 裁掉
  （對**任何**移除的最底列都成立，不只是清空）；「尚無通知」文案只在離開視窗結束之後才掛上。
  宿主收攏動效時（`prefers-reduced-motion`、動畫匯流排 park 標記、或
  `html[data-css-animations="0"]`）會整體跳過這段保持，文案立刻交接。

## 參考實作

`runtime/notificationCenter.ts`（帳本與各源記帳掛鉤）+
`components/HkNotificationBell.tsx`（鈴鐺 + 面板一體組合）。
資料源經 `recordNotification` / `setNotificationState` 寫入；
宿主掛 `<HkNotificationBell />` 並決定它住在哪。

宿主記帳的 id 與內建鏡像共用同一個扁平字串空間：`toast:` / `blocking:` / `emergency:` 前綴為內建保留——宿主記錄駐留 chip 或自訂條目時自選前綴（如 `myapp:`），自訂 id 永遠不可能劫持內建 episode。

## 緊急行例外

緊急行是唯一的例外：episode **存續期間**（active 或 snoozed）該行**不帶消除鈕**——其帳本條目持有該警報唯一的恢復句柄，且輪詢 re-raise 會復活被刪的行。已恢復（cleared）的緊急是記錄，用戶可消除；活著的 episode 從不被用戶消除。
