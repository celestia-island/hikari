# 頁面骨架：動作區語法

管理與主控台頁面共用同一份頁頭契約：頁面透過「宣告用途的槽位」擁有右上角動作區，
頁面的主要入口住在動作區裡——而不是頁面正文裡。

## 規範槽位

每個註冊都宣告一個用途；動作區按槽位的固定次序渲染，與視圖註冊的先後無關：

```text
[新增][篩選][搜尋][重新整理][視窗]
```

用途不屬於規範槽位的註冊是自訂項：排在規範區之後、按註冊的逆序由右向左填充，
規範區永遠不被擠動。

## 新增規則

頁面的主建立動作——建立一個新的頂層實體（一個提供者、一個頻道、一個群組、一條
準入規則、共享主題線上的一套主題）——是**右上角動作區裡的加號圖示按鈕，位於重新整理
左邊**。它絕不是頁面正文裡的獨立按鈕。

原本印在正文按鈕上的可見文案，成為該按鈕的無障礙名稱與懸浮提示；建立用的對話框
仍由頁面自己擁有。

**局部新增不受此限。** 在編輯器、對話框、精靈或卡片內部的子清單裡加一列（「新增
模型列」「新增成員」「新增掛載方案」）屬於那層局部語法，不是頁面的建立動作，留在
原地。

## 幾何

動作區是一整排 chrome：每個圖示按鈕都走同一套尺寸階梯（`useChromeActionSize`），
圖示配 16px。一個寫死尺寸的按鈕混在階梯尺寸的鄰居中間，會被讀成另一族按鈕——
用共享的組合式函式組裝動作區，不要手釘尺寸。

## 參考實作

chrome 由 hikari 提供：`HkAdminHeader` 的動作列、`HkIconButton` 與
`useChromeActionSize`。宿主經渲染上述槽位的 `provideActionBar` /
`useActionBar` composable 對註冊；它是這套語法的參考實作。

## 行動端摺疊

錨定在頁首中槽或頁尾中槽的按鈕組，在手機寬度視口（<768，`useBreakpoint().isMobile`——
sheet 家族的閾值）摺疊為：原按鈕組變成一個讀出**當前項**的下拉式觸發鈕，選項
以底部 sheet 展開（`HkSelectPanel` 的 `sheetOnMobile`）。兩套形態共用同一份
value 契約，`?tab=` 深鏈跨斷點不受影響。`HkAdaptiveTabs` 是預設實作；
自帶專屬行的動態項目列表切換器（平台切換器）是豁免的特例，不是可照抄的模式。

## 頁尾角落文字

頁眉/頁尾的六個角落（左/中/右 ×2）顯示文字，一律用 hikari 的 `HkCornerText`：
一個實例 = 一個角落的一條文字道。

- `align` 決定對齊：`start`（左角）/`center`（中道）/`end`（右角）；條目換行後
  繼續貼著同一側——右角的文字折行仍靠右。
- 條目是 `nowrap` 原子：條目**之間**換行，條目內部永不折行（備案號不得斷在
  序號中間）。
- 預設 chrome 弱墨（`text-2xs` + 0.6 不透明度）；`muted: false` 恢復全墨。
- 一個角落要多行（識別行 + 備案行）就縱向堆疊多個實例——固定 3rem 狀態帶內
  容得下兩行 text-2xs。
- 連結條目（備案連結）用 `items` + `as="nav"` + `ariaLabel`；自由內容（狀態
  晶片）走預設插槽，排在 `items` 之後。

宿主不得再手寫 `flex-wrap: nowrap` 的單行擠壓道，也不得讓文字溢出固定高度帶。
參考實作：`HkCornerText`。
