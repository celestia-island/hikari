# 頁面骨架：動作區語法

管理與主控台頁面共用同一份頁頭契約：頁面透過「宣告用途的槽位」擁有右上角動作區，
頁面的主要入口住在動作區裡——而不是頁面正文裡。

## 規範槽位

每個註冊都宣告一個用途；動作區按槽位的固定次序渲染，與視圖註冊的先後無關：

```text
[新增][篩選][搜尋][重新整理][視窗]
```

用途不屬於規範槽位的註冊是自訂項：排在規範區之後、按註冊的逆序由右向左填充，
規範區永遠不被擠動。

## 新增規則

頁面的主建立動作——建立一個新的頂層實體（一個提供者、一個頻道、一個群組、一條
準入規則、共享主題線上的一套主題）——是**右上角動作區裡的加號圖示按鈕，位於重新整理
左邊**。它絕不是頁面正文裡的獨立按鈕。

原本印在正文按鈕上的可見文案，成為該按鈕的無障礙名稱與懸浮提示；建立用的對話框
仍由頁面自己擁有。

**局部新增不受此限。** 在編輯器、對話框、精靈或卡片內部的子清單裡加一列（「新增
模型列」「新增成員」「新增掛載方案」）屬於那層局部語法，不是頁面的建立動作，留在
原地。

## 幾何

動作區是一整排 chrome：每個圖示按鈕都走同一套尺寸階梯（`useChromeActionSize`），
圖示配 16px。一個寫死尺寸的按鈕混在階梯尺寸的鄰居中間，會被讀成另一族按鈕——
用共享的組合式函式組裝動作區，不要手釘尺寸。

## 參考實作

chrome 由 hikari 提供：`HkAdminHeader` 的動作列、`HkIconButton` 與
`useChromeActionSize`。宿主經渲染上述槽位的動作區上下文註冊；chest webui 的
`useActionBar` / `usePageCreateAction` 是這套語法的參考實作。
